DATABASE MANAGEMENT SYSTEMS (DBMS) COURSE NOTES

UNIT 1: INTRODUCTION TO DATABASE SYSTEMS & RELATIONAL MODEL
A Database Management System (DBMS) is software designed to store, manage, and facilitate access to structured data. The relational model, introduced by E.F. Codd, represents data as relations (tables) consisting of tuples (rows) and attributes (columns). Primary keys uniquely identify tuples within a relation, while foreign keys enforce referential integrity between related relations. Structured Query Language (SQL) provides declarative syntax for Data Definition Language (DDL), Data Manipulation Language (DML), and Data Control Language (DCL). Relational algebra forms the theoretical foundation of SQL with fundamental operations including Selection (sigma), Projection (pi), Cartesian Product (cross), Union (cup), Difference (-), and Join (bowtie).

UNIT 2: FUNCTIONAL DEPENDENCIES & RELATIONAL NORMALIZATION
Normalization is the process of structuring relational schemas to minimize data redundancy and prevent insertion, update, and deletion anomalies. A functional dependency X -> Y states that if two tuples agree on attributes X, they must also agree on attributes Y. Armstrong's Axioms provide sound and complete inference rules: Reflexivity, Augmentation, and Transitivity. First Normal Form (1NF) requires all attribute domains to be atomic. Second Normal Form (2NF) enforces 1NF and requires that every non-prime attribute is fully functionally dependent on any candidate key (eliminating partial dependencies). Third Normal Form (3NF) enforces 2NF and mandates that no non-prime attribute is transitively dependent on candidate keys. Boyce-Codd Normal Form (BCNF) strictly requires that for every non-trivial functional dependency X -> Y, X must be a superkey. Lossless join decomposition and dependency preservation ensure data integrity during schema normalization.

UNIT 3: TRANSACTION MANAGEMENT & ACID PROPERTIES
A transaction is a logical unit of database processing that includes one or more database access operations. To maintain data integrity, transactions must satisfy the ACID properties:
1. Atomicity: All operations in a transaction are executed successfully to completion or none are executed (All-or-Nothing). Managed by the database recovery manager using write-ahead logging (WAL).
2. Consistency: Execution of a transaction in isolation preserves the consistency of the database, transforming it from one valid state to another valid state according to schema constraints.
3. Isolation: The execution of concurrent transactions does not interfere with each other; intermediate uncommitted states are hidden from other transactions. Managed by concurrency control protocols.
4. Durability: Once a transaction commits, its modifications persist permanently in non-volatile storage, even in the event of subsequent system crashes or power failures.

UNIT 4: CONCURRENCY CONTROL & SERIALIZABILITY
Concurrency control ensures safe interleaved execution of transactions in multi-user database environments. The goal is conflict serializability, where a non-serial execution schedule is conflict-equivalent to some serial schedule. Conflict serializability is verified using Precedence Graphs (Serialization Graphs); an execution schedule is conflict serializable if and only if its precedence graph contains no directed cycles.
Two-Phase Locking (2PL) guarantees conflict serializability through two distinct phases: Growing Phase (locks may be acquired, no locks released) and Shrinking Phase (locks may be released, no locks acquired). Strict 2PL holds all exclusive locks until transaction commit or abort, avoiding cascading aborts. Rigorous 2PL holds both shared and exclusive locks until completion.
Deadlocks occur when two or more transactions are in a circular wait state for locks held by each other. Deadlock handling includes prevention (Wait-Die and Wound-Wait timestamp schemes) and detection using Wait-For Graphs (WFG) combined with victim selection for rollback.

UNIT 5: INDEXING STRUCTURES & B+ TREES
Indexing enhances query performance by minimizing disk block I/O accesses during data retrieval. Primary indexes are defined on ordered data files sorted by the primary key. Secondary indexes are constructed on non-ordering fields.
B+ Trees are balanced multi-level search trees widely adopted in database storage engines:
1. Self-balancing: All leaf nodes are located at the exact same depth.
2. Structure: Internal nodes contain search keys and child pointers to direct searches, while leaf nodes store the actual record pointers or clustered data rows.
3. Linked Leaves: Leaf nodes are linked sequentially via bidirectional pointers, enabling highly efficient range queries and sequential scans.
4. Order and Occupancy: In a B+ tree of order p, each non-root node maintains at least ceil(p/2) pointers, maintaining high storage density with O(log N) lookup, insertion, and deletion complexity.

UNIT 6: QUERY PROCESSING & OPTIMIZATION
Query processing transforms high-level SQL declarative queries into low-level procedural execution plans. The database query engine executes parsing and translation, relational algebra optimization, and query evaluation. Cost-based query optimizers estimate disk I/O, CPU time, and memory usage for alternative query execution plans using database catalog statistics. Relational algebra heuristic rules push selections and projections as early as possible down the operator tree to reduce intermediate relation cardinalities before performing costly join algorithms like nested-loop join, sort-merge join, or hash join.
